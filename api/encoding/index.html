    API reference: encoding¶

    qimp.encoding.frqi¶

    qimp.encoding.frqi ¶

    FRQI encoding: Flexible Representation of Quantum Images.

    A 2^n × 2^n grayscale image is encoded into 2n+1 qubits: 2n position qubits plus 1 color qubit. The pixel intensity is mapped to an RY rotation angle and applied via a fully-controlled RY gate. Multiple images can be stacked by adding m = ceil(log2(num_images)) selection qubits, for a total of 2n+m+1 qubits.

    Scales freely with n (image side = 2^n) and m (number of stacked images = 2^m).

    Reference: P.Q. Le, F. Dong, K. Hirota, Quantum Inf. Process. 10 (2011) 63-84.

    FrqiEncoder ¶

    Stateful FRQI encoder.

    Bundles the normalization factor and inferred n/m so the same instance can be reused for encode→measure→decode round-trips.

    intensities_to_angles ¶

    intensities_to_angles(intensities: ndarray, normalization: float) -> np.ndarray

    Map pixel intensities to RY angles in [0, π].

    Convention: intensity 0 → θ = 0, intensity = normalization → θ = π. After RY(θ), prob(color qubit = 1) = sin²(θ/2) = intensity / normalization.

    frqi_circuit ¶

    frqi_circuit(images: ndarray | Sequence[ndarray], *, normalization: float | None = None) -> QuantumCircuit

    Build an FRQI quantum circuit for one or more square images.

    Parameters:

    Name Type Description Default
    images ndarray | Sequence[ndarray]

    A single 2D image (shape (2^n, 2^n)), a 3D stack (shape (num_images, 2^n, 2^n)), or a sequence of 2D images. When more than one image is supplied, num_images is padded with zero images to the next power of two and m = log2(num_images_padded) selection qubits are added.

    		 required
    normalization float | None

    Intensity that maps to angle π (full color amplitude on |1⟩). Defaults to the max value of the dtype (255 for uint8, 65535 for uint16, 1.0 for float).

    		 None

    Returns:

    Type Description
    QuantumCircuit

    Circuit with 2n + m + 1 qubits and an equal number of classical bits. No measurement gates are appended; call ideal_simulation / device_test on the returned circuit (they add measurements automatically).

    frqi_decode ¶

    frqi_decode(counts: dict[str, int], n: int, m: int = 0, normalization: float = 1.0) -> np.ndarray | list[np.ndarray]

    Decode measurement counts from an FRQI circuit into one or more images.

    Parameters:

    Name Type Description Default
    counts dict[str, int]

    Qiskit-style histogram from ideal_simulation(qc, shots).

    		 required
    n int

    Number of spatial qubits per axis (image side = 2^n).

    		 required
    m int

    Number of selection qubits (number of images = 2^m). Defaults to 0 (single image).

    		 0
    normalization float

    Intensity that maps to θ = π — must match what was used at encoding. The reconstructed intensity for pixel j of image s is prob(color=1 | pos=j, sel=s) * normalization.

    		 1.0

    Returns:

    Type Description
    ndarray | list[ndarray]
    • When m == 0 (single image): a single (2^n, 2^n) float array, matching the shape contract of neqr_decode / qpie_decode.
    • When m > 0: a list of 2^m images, since only FRQI supports multi-image encoding via image-selection qubits.

    qimp.encoding.neqr¶

    qimp.encoding.neqr ¶

    NEQR encoding: Novel Enhanced Quantum Representation.

    A 2^n × 2^n grayscale image with intensity resolution 2^q is encoded into 2n + q qubits. The intensity is stored in a separate q-bit register (basis-state encoding), enabling exact retrieval and arithmetic operations.

    Qubit layout (low → high index): - q intensity qubits (qubits 0 … q-1) - n X-position qubits (qubits q … q+n-1) - n Y-position qubits (qubits q+n … q+2n-1)

    Reference: Y. Zhang et al., Quantum Inf. Process. 12 (2013) 2833-2860.

    NeqrEncoder ¶

    Stateful NEQR encoder that records n and q for round-trips.

    neqr_circuit ¶

    neqr_circuit(image: ndarray, q: int = 8) -> QuantumCircuit

    Build a NEQR circuit for a single grayscale image.

    Parameters:

    Name Type Description Default
    image ndarray

    Square (2^n, 2^n) integer array with values in [0, 2^q - 1].

    		 required
    q int

    Number of intensity qubits. Image values must fit in q bits.

    		 8

    Type Description
    QuantumCircuit

    Circuit with 2n + q qubits.
    Notes

    Complexity: O(q · n · 2^(2n)) gates worst-case. Scales freely with both n and q.

    neqr_decode ¶

    neqr_decode(counts: dict[str, int], n: int, q: int) -> np.ndarray

    Decode NEQR measurement counts into the reconstructed image.

    For each position, the most-frequent intensity reading is taken (NEQR is exact, so ideal simulations yield a single intensity per pixel).

    qimp.encoding.qpie¶

    qimp.encoding.qpie ¶

    QPIE encoding: Quantum Probability Image Encoding.

    Pixel intensities are normalized so that their squared values sum to 1, then loaded as amplitude probabilities into 2n qubits via Qiskit's initialize. Compact (only 2n qubits) but produces an arbitrary state preparation that transpiles to deep circuits.

    Reference: X.-W. Yao et al., Phys. Rev. X 7 (2017) 031041.

    QpieEncoder ¶

    Stateful QPIE encoder that records n and the RMS for decoding.

    normalize_amplitudes ¶

    normalize_amplitudes(image: ndarray) -> tuple[np.ndarray, int, float]

    Convert a square 2^n × 2^n image into QPIE amplitudes.

    Returns:

    Type Description
    amplitudes

    Length-2^(2n) float64 array with Σ amplitudes² = 1.
    n

    log2(side).
    rms

    Root-mean-square of the original intensities: √(mean(I²)). Forward this to qpie_decode to recover gradient or intensity units. Zero if the input image is all-zero (in which case a uniform-superposition fallback is emitted and a warning is raised).

    Raises:

    Type Description
    ValueError

    If the image is not square, side is not a power of two, or any intensity is negative.

    qpie_circuit ¶

    qpie_circuit(image: ndarray) -> QuantumCircuit

    Build a QPIE circuit for a single grayscale image.

    The circuit has 2n qubits; the state is |Ψ⟩ = Σ_i (I_i / ‖I‖) |i⟩ where |i⟩ is the position basis state.

    Scales freely with n. The intensity resolution is bounded only by the number of measurement shots (no q parameter — QPIE has no intensity register).

    qpie_decode ¶

    qpie_decode(counts: dict[str, int], n: int, rms: float = 1.0) -> np.ndarray

    Decode QPIE measurement counts into a reconstructed image.

    Parameters:

    Name Type Description Default
    counts dict[str, int]

    Histogram from ideal_simulation(qpie_circuit(image), shots).

    		 required
    n int

    Number of spatial qubits per axis (image side = 2^n).

    		 required
    rms float

    Root-mean-square of the original intensities, √(mean(I²)). Returned by QpieEncoder.encode(); if unknown, leave 1.0 to recover the normalized image (the absolute scale of QPIE is not preserved).

    		 1.0

    qimp.encoding.mcrqi¶

    qimp.encoding.mcrqi ¶

    MCRQI encoding: FRQI extension to RGB images.

    A 2^n × 2^n RGB image is encoded into 2n + 3 qubits: 2n position qubits and 3 color qubits (one per channel R / G / B). Each color qubit independently carries the channel's pixel intensity as an RY rotation angle.

    Compared to FRQI: - adds 2 qubits (3 color qubits instead of 1); - per-pixel construction is 3 fully-controlled RY gates instead of 1.

    Reference: B. Sun et al., J. Adv. Comput. Intell. Intell. Inform. 17 (2013) 404-417.

    qimp.encoding.ncqi¶

    qimp.encoding.ncqi ¶

    NCQI encoding: NEQR extension to RGB images.

    A 2^n × 2^n RGB image with intensity resolution 2^q per channel is encoded into 2n + 3q qubits. The intensity of each channel sits in its own q-bit basis-state register; retrieval is exact.

    Qubit layout (low → high index): - q R-intensity qubits (qubits 0 … q-1) - q G-intensity qubits (qubits q … 2q-1) - q B-intensity qubits (qubits 2q … 3q-1) - n X-position qubits (qubits 3q … 3q+n-1) - n Y-position qubits (qubits 3q+n … 3q+2n-1)

    Reference: J. Sang, S. Wang, Q. Li, Quantum Inf. Process. 16 (2017) 42.

    qimp.encoding.compression¶

    qimp.encoding.compression ¶

    FRQI / NEQR compression via Boolean-function minimisation.

    Pixels that share the same intensity (FRQI) or the same intensity-bit (NEQR) form a Boolean function of the position bits. Minimising that function shrinks the number of control patterns needed, which reduces the per-pixel multi-controlled gates issued by the encoder.

    Two self-contained minimisers are provided, with no extra dependency:

    • Quine–McCluskey (compress_minterms) followed by a greedy disjoint cover. Used by default for small position registers.
    • An ESPRESSO-style heuristic (espresso_minimize: EXPAND / IRREDUNDANT / REDUCE on cube covers) followed by make_disjoint_cover. Used by default for 2n >= ESPRESSO_AUTO_MIN_WIDTH (n >= 5), where enumerating all prime implicants becomes expensive.

    Both paths return a disjoint cover that reproduces the on-set exactly, which the encoders require. Select the path with method="auto" | "qm" | "espresso" on FrqiCompressor, NeqrCompressor or position_strings_to_implicants.

    References
    • W. V. Quine, "The problem of simplifying truth functions", Amer. Math. Monthly 59 (1952); E. J. McCluskey, "Minimization of Boolean functions", Bell Syst. Tech. J. 35 (1956).
    • R. K. Brayton, G. D. Hachtel, C. T. McMullen, A. L. Sangiovanni-Vincentelli, "Logic Minimization Algorithms for VLSI Synthesis", Kluwer (1984).

    compress_minterms ¶

    compress_minterms(minterms: Iterable[str]) -> list[str]

    Return prime implicants for a Boolean function given by minterms.

    Each input is a fixed-width binary string. Output strings use "-" for don't-cares. The set returned covers every minterm in minterms (no further essential-prime-implicant selection — the result is a cover, not necessarily the smallest one).

    For typical FRQI/NEQR uses (n ≤ 4) this is fast and correct. For larger fan-ins use espresso_minimize.

    espresso_minimize ¶

    espresso_minimize(minterms: Iterable[str], dont_cares: Iterable[str] = ()) -> list[str]

    Heuristic two-level minimisation of a single-output Boolean function.

    Pure-Python ESPRESSO-style loop: the on-set is expanded into prime cubes against the off-set (EXPAND), redundant cubes are removed (IRREDUNDANT), then the cover is repeatedly reduced (REDUCE), re-expanded and made irredundant until the cost (number of cubes, then number of literals) stops decreasing.

    Parameters:

    Name Type Description Default
    minterms Iterable[str]

    On-set, as fixed-width strings over "0", "1" (and optionally "-", so cubes are accepted too). MSB first.

    		 required
    dont_cares Iterable[str]

    Optional DC-set in the same format. The result may cover any part of it.

    		 ()

    Returns:

    Type Description
    list[str]

    Sorted implicant strings. Their union contains the on-set and is contained in on-set plus DC-set. The cubes are prime and irredundant but may overlap; see make_disjoint_cover for an exact partition. The cover is not guaranteed to be minimum.

    make_disjoint_cover ¶

    make_disjoint_cover(cover: Iterable[str]) -> list[str]

    Rewrite a cover as pairwise disjoint implicants with the same union.

    Cubes are taken largest first; each new cube is cut by disjoint sharp against every cube already placed, then adjacent pieces are merged. Every output cube contains at least one minterm, so the result never has more cubes than the function has minterms.

    position_strings_to_implicants ¶

    position_strings_to_implicants(positions: Iterable[int], width: int, *, method: CompressionMethod = 'auto') -> list[str]

    Pixel indices → disjoint cover of width-bit implicants.

    With method="qm", runs Quine–McCluskey to find prime implicants, then greedy set-partitioning to ensure the returned implicants do not overlap on any minterm. With method="espresso", runs espresso_minimize and then make_disjoint_cover. method="auto" uses Quine–McCluskey for width < ESPRESSO_AUTO_MIN_WIDTH and ESPRESSO otherwise.

    Either way the result covers each given position exactly once and no other position, so it can be turned directly into a sequence of multi-controlled gates.
