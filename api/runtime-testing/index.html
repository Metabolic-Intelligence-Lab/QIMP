    API reference: runtime and testing¶

    qimp.testing¶

    Test harnesses: ideal/noisy simulation and IBM Quantum hardware execution.

    ideal_simulation ¶

    ideal_simulation(qc: QuantumCircuit, shots: int = 8192, *, seed: int | None = None) -> Counts

    Run on a noise-free Aer simulator and return counts.

    Pass seed to make the shot sampling reproducible (for a given Aer version).

    exact_counts ¶

    exact_counts(qc: QuantumCircuit, *, total: int = 1000000) -> Counts

    Return the noise-free counts dict from a statevector simulation.

    This is the deterministic equivalent of ideal_simulation for tests of exact encoders (NEQR / NCQI / compression): no shot noise, no flakiness at higher n/q. Uses :class:qiskit.quantum_info.Statevector to compute each basis-state probability exactly, then rescales by total and rounds — every non-zero probability appears in the result.

    Parameters:

    Name Type Description Default
    qc QuantumCircuit

    Circuit to evaluate (no need to attach measurements; the statevector is computed before any measurement op).

    		 required
    total int

    Synthetic "shots" count to multiply probabilities by. Choose a value ≫ 2^num_qubits so rounding doesn't drop tiny but real amplitudes.

    		 1000000

    noisy_simulation ¶

    noisy_simulation(qc: QuantumCircuit, shots: int = 8192, noise_model: NoiseModel | None = None) -> Counts

    Run on an Aer simulator with a noise model and return counts.

    If noise_model is None, runs with the simulator's default noise (none). Pass a qiskit_aer.noise.NoiseModel.from_backend(backend) for realistic device noise.

    qimp.runtime.ibm¶

    qimp.runtime.ibm ¶

    IBM Quantum Runtime helpers — service singleton, backend resolution, hardware execution via SamplerV2 with TREX + DD mitigation and counts-side zero-noise extrapolation, Aer noise-model fallback, and per-run artifact persistence.

    All IBM-Runtime imports are local to this module: the rest of the library imports only the typed helpers exposed here.

    fold_gates ¶

    fold_gates(qc: QuantumCircuit, scale: float, *, target: Any | None = None) -> QuantumCircuit

    Return qc with its gate noise amplified by global unitary folding.

    The unitary part U (everything before the final measurements) is replaced by U (U^dag U)^k. For an odd integer scale this gives k = (scale - 1) / 2 full folds (1 -> U, 3 -> U U^dag U, ...). For other values the fractional remainder is realised by also folding the last m gates L of U once (... L^dag L), with m chosen so that the achieved scale 1 + 2k + 2m/d (d = number of gates in U) is as close as possible to the request. The achieved scale is stored in folded.metadata["zne_fold_scale"].

    Final measurements (and the barriers just before them) are kept once, at the end. Barriers on the active qubits separate the copies, so a later optimisation pass cannot cancel U^dag U. Fold after transpilation to the device ISA, and pass the device target so the inverse gates (sxdg, rz(-t), ...) are rewritten into the basis without optimisation; the circuit layout is preserved.

    Parameters:

    Name Type Description Default
    qc QuantumCircuit

    Circuit to fold, ideally already transpiled to the device ISA. Measurements, if any, must all be final.

    		 required
    scale float

    Requested noise scale, >= 1. Odd integers give full folds.

    		 required
    target Any | None

    Optional transpiler Target. When given, gates outside its basis (introduced by the inverse) are translated into it.

    		 None

    Returns:

    Type Description
    QuantumCircuit

    The folded circuit, with the achieved scale in metadata["zne_fold_scale"].

    Raises:

    Type Description
    ValueError

    For scale < 1, mid-circuit measurements, or other non-unitary operations (reset, control flow) in the unitary part.

    zne_probabilities ¶

    zne_probabilities(counts_per_scale: Sequence[Mapping[str, float]], scales: Sequence[float], *, method: str = 'richardson') -> dict[str, float]

    Extrapolate bitstring probabilities to zero noise.

    Each counts_per_scale[i] is normalised to a probability distribution, and for every bitstring seen at any scale p(scale) is extrapolated to scale = 0. Negative estimates are clipped to zero and the result is renormalised to sum to one.

    Parameters:

    Name Type Description Default
    counts_per_scale Sequence[Mapping[str, float]]

    One counts (or probabilities) dict per noise scale.

    		 required
    scales Sequence[float]

    Noise scales matching counts_per_scale; at least two, distinct.

    		 required
    method str

    "richardson": polynomial of degree len(scales) - 1 through all points (exact for a quadratic trend with three scales). "linear": least-squares straight line. "exponential": p = 2^-n + B exp(-c scale), the decay of a global depolarising channel, with a linear fallback per bitstring.

    		 'richardson'

    Returns:

    Type Description
    dict[str, float]

    Zero-noise probabilities; bitstrings with zero estimate are dropped.

    Raises:

    Type Description
    ValueError

    For an unknown method, mismatched lengths, fewer than two distinct scales, empty counts, or an all-zero estimate.

    aer_noisy_run ¶

    aer_noisy_run(qc: QuantumCircuit, *, backend: Any, shots: int = 4096, zne_scales: Sequence[float] | None = None, zne_method: str = 'richardson', seed: int | None = None) -> dict[str, int]

    Run qc on an Aer simulator wired with backend's noise model.

    Uses :func:AerSimulator.from_backend which inherits the device's noise + coupling map + basis gates. Adds measure_all() if the circuit has no measurements (reuses qimp.testing._ensure_measured).

    When zne_scales is given (e.g. (1, 3, 5)), the transpiled circuit is folded at each scale with :func:fold_gates, all folded circuits are simulated with shots shots each, and the zero-noise extrapolated counts (:func:zne_extrapolate with zne_method) are returned instead of the raw counts. seed fixes both the transpiler and the simulator seed.

    hw_run ¶

    hw_run(qc: QuantumCircuit, *, backend: Any, shots: int = 4096, mitigation: str = 'trex+dd', dd_sequence: str = 'XY4', optimization_level: int = 3, timeout_s: float = 1200.0, zne_scales: Sequence[float] = DEFAULT_ZNE_SCALES, zne_method: str = 'richardson') -> tuple[dict[str, int], QuantumCircuit, str, dict[str, Any]]

    Submit qc to backend via SamplerV2 with TREX + DD mitigation.

    Returns (counts, transpiled_qc, job_id, transpile_summary).

    Parameters:

    Name Type Description Default
    qc QuantumCircuit

    The quantum circuit to run (measurements added automatically if absent).

    		 required
    backend Any

    An IBM backend object (real or fake).

    		 required
    shots int

    Number of shots.

    		 4096
    mitigation str

    'trex+dd' enables twirled readout error extinction and dynamical decoupling (default). 'trex' enables only TREX, 'dd' enables only DD, 'none' disables all mitigation. 'zne' adds counts-side zero-noise extrapolation on top of TREX+DD: the transpiled ISA circuit is folded at each of zne_scales with :func:fold_gates, the folded circuits are submitted as separate pubs of one SamplerV2 job, and each bitstring probability is extrapolated to zero noise with :func:zne_extrapolate. The returned counts are the extrapolated counts rescaled to shots; transpiled_qc is the unfolded circuit. The five modes together support ablation studies of which layer contributes the recovered signal.

    		 'trex+dd'
    dd_sequence str

    Decoupling sequence used when mitigation includes DD. 'XY4' (default) is the sequence used throughout the paper's campaign. 'XpXm' and 'XX' are the matched-pulse-count pair: both insert two pulses per idle window with identical timing, but XpXm's +/- alternation cancels pulse-amplitude error to first order while XX accumulates it, so the contrast between them separates a coherent pulse-error mechanism from an incoherent one (§7.4). These three are what SamplerV2 exposes.

    		 'XY4'
    optimization_level int

    Transpiler optimisation level (0–3). Defaults to 3.

    		 3
    timeout_s float

    timeout_s is currently advisory; recovery of long-running jobs is handled by the caller (the CLI sweep script in Task 15 persists job_id before awaiting job.result()).

    		 1200.0
    zne_scales Sequence[float]

    Noise scales for mitigation='zne' (default (1, 3, 5)). Odd integers give full global folds; other values add a partial fold of the last gates. Ignored by the other modes.

    		 DEFAULT_ZNE_SCALES
    zne_method str

    Extrapolation model for mitigation='zne': 'richardson' (default), 'linear' or 'exponential'.

    		 'richardson'

    Returns:

    Type Description
    tuple

    (counts, transpiled_qc, job_id, transpile_summary). With mitigation='zne' the summary also holds zne_scales, zne_achieved_scales (used as the abscissa), zne_method, per-scale zne_depths and zne_two_q_gate_counts, and the raw per-scale counts zne_raw_counts, so callers that persist the summary keep everything needed to redo the fit.

    qimp.runtime.zne¶

    qimp.runtime.zne ¶

    Counts-side zero-noise extrapolation (ZNE) helpers.

    SamplerV2 exposes no ZNE option, so ZNE on bitstring distributions is done by hand in two steps:

    1. :func:fold_gates amplifies the gate noise of a circuit by global unitary folding, U -> U (U^dag U)^k, optionally with a partial fold of the last gates for fractional scales. Final measurements are kept at the end and never folded.
    2. :func:zne_extrapolate (or :func:zne_probabilities) fits each bitstring probability as a function of the noise scale and evaluates the fit at zero noise.

    Folding is meant to be applied to a circuit that is already transpiled to the target ISA: the copies are separated by barriers and the inverse gates are rewritten into the target basis without optimisation, so nothing cancels U^dag U afterwards. Only gate noise is amplified; readout error is not scaled by folding and is left to TREX or another readout method.

    qimp.runtime.memory_pool¶

    qimp.runtime.memory_pool ¶

    Pre-allocated buffer pool for batch image processing.

    Avoids repeated np.zeros((H, W)) allocations when processing large datasets of same-shape images. Buffers are reused round-robin.

    MemoryPool ¶

    Round-robin pool of (H, W) image buffers and flattened angle buffers.

    Parameters:

    Name Type Description Default
    max_buffers int

    How many buffers to pre-allocate.

    		 required
    image_size int

    Side length of square buffers. Image buffer shape = (image_size, image_size), angle buffer shape = (image_size * image_size,).

    		 required
    dtype type

    Dtype of the buffers (default float32 — half the RAM of float64).

    		 float32
    Notes

    No upper bound on image_size. With float32 and image_size=2^n × 2^n, one buffer costs 4 * 4^n bytes. A typical pool with 50 buffers at n=7 (128×128) uses ~3.2 MB; at n=10 (1024×1024) it uses ~200 MB.

    Advances the round-robin cursor: consecutive calls return distinct buffers, wrapping around after max_buffers calls.

    get_angle_buffer ¶

    qimp.runtime.caching¶

    qimp.runtime.caching ¶

    LRU-cached circuit construction wrappers.

    The base FRQI/NEQR/QPIE circuits depend only on the qubit counts, so it pays to cache the empty register layout and clone it for each new image.

    base_frqi_circuit cached ¶

    base_frqi_circuit(n: int, m: int = 0) -> QuantumCircuit

    Return an empty FRQI scaffold for a 2^n × 2^n image and m selection qubits.

    Layout: 2n position qubits | m image-selection qubits | 1 color qubit. Hadamards are pre-applied to the 2n position qubits.

    The returned circuit is shared: callers must .copy() before mutating. Scales with n and m without bound (caller's RAM is the only limit).

    adaptive_shots(circuit_depth: int, convergence_history: list[float] | None = None, base_shots: int = 10000, min_shots: int = 1000, max_shots: int = 100000) -> int

    Pick a shot count for the next variational iteration.

    Heuristic: - If the last 3 objective values are within stddev < 0.01, halve base_shots. - Otherwise scale base_shots linearly with circuit_depth / 50, capped at 2x.
